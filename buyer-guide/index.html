Installation

1
Unzip and open the project
unzip payload-portfolio.zip
cd payload-portfolio
2
Install dependencies
pnpm install
3
Copy the env template
cp .env.example .env.local

Open .env.local in your editor and fill in the values. See the Environment Variables section below.

4
Start the development server
pnpm dev

The app runs on http://localhost:3000. The Payload admin panel is at http://localhost:3000/admin.

5
Create your admin account

On first visit to /admin, Payload will prompt you to create the first user. This is your admin account — use a strong password.

💡 The first user created becomes the super-admin. Subsequent users can be created in the Users collection inside the admin panel.
6
Fill in your identity

In the admin panel, go to Globals → Site Settings and fill in the Identity, Social Links, and Engineering Philosophy sections. Your name and role will appear across the site immediately.

7
Populate your content

Add entries to Timeline (career history), Work (case studies), Projects (side projects), Education, and Certifications via the admin panel.

8
Edit your tech stack

The only file you need to edit in code is content/stack.ts. Open it and replace the entries with your own technologies and proficiency levels.

⚠️ This is the only source file buyers need to edit. Everything else is managed via the admin panel.

Environment Variables

Copy .env.example to .env.local and fill in each value. Never commit .env.local to git.

Core (required)

VariableDescription & Where to Get It
PAYLOAD_SECRET Any long random string (32+ chars). Used to sign auth tokens.
Generate: openssl rand -base64 32
MONGODB_URI MongoDB connection string.
Atlas: Database → Connect → Drivers → copy the URI, replace <password>
NEXT_PUBLIC_SITE_URL Your canonical site URL, e.g. https://janedoe.dev.
Use http://localhost:3000 during local development.
PREVIEW_SECRET Any random string. Protects the draft-mode preview route.
Generate: openssl rand -base64 16

Cloudflare R2 (required for media uploads)

VariableDescription
R2_ACCOUNT_ID Cloudflare Account ID — found in the right sidebar of any Cloudflare dashboard page.
R2_ACCESS_KEY_ID R2 API Token → Access Key ID. Create under R2 → Manage R2 API Tokens.
R2_SECRET_ACCESS_KEY R2 API Token Secret — shown once on creation. Copy it immediately.
R2_BUCKET_NAME The name of your R2 bucket (e.g. my-portfolio-media).
R2_PUBLIC_URL Public CDN URL for your bucket (e.g. https://pub-xxxx.r2.dev). Enable public access in the bucket settings to get this URL.
NEXT_PUBLIC_MEDIA_URL Same value as R2_PUBLIC_URL. Used client-side by the Next.js image loader.

Folder Structure

The project follows Next.js App Router conventions. Each row shows the path on the left and what it does on the right.

Path Description

Key Files Explained

content/stack.ts edit this

The only source file buyers need to modify. It exports a structured list of your technologies grouped by discipline (Backend, Frontend, DevOps, etc.) with a maturity level for each. Open it and replace the entries with your own stack.

globals/SiteSettings.ts cms schema

Defines the shape of the Site Settings global in the Payload admin. You never edit this file — you edit the data through the admin panel at /admin → Globals → Site Settings.

lib/site-identity.ts

Defines the SiteIdentity type and buildIdentity() function. Merges CMS data with safe fallback defaults so the site renders correctly even if the admin hasn't been populated yet.

payload.config.ts

Registers all Payload collections, globals, plugins (SEO, Search, Form Builder, MCP, S3 storage), and the email adapter. Modify with care — wrong changes here can break the admin panel.

lib/data.ts

All cached data fetchers. Each function wraps a Payload REST call in unstable_cache with revalidation tags. This is why page loads are fast — content is cached and only re-fetched when you save in the admin.

Site Settings (CMS)

All personal identity is managed here. Go to Globals → Site Settings in the admin panel.

Identity

Your name, handle (Twitter/X username), role/title, location, timezone, email address, site URL, and meta description. These power the nav label, footer, page titles, Open Graph tags, and structured data.

Fields: name · handle · role · location · timezone · email · siteUrl · description
Social Links

Up to 6 social profiles. Each entry has a platform (GitHub, LinkedIn, Instagram, Twitter, YouTube), a URL, and an optional display label. These appear in the footer and the writing CTAs.

Engineering Philosophy

Up to 5 philosophy pillars shown on the homepage. Each pillar has a title and a body paragraph. The display number (01, 02, …) is derived from the array order automatically.

Hero Copy

Eyebrow label, headline, and subheadline shown in the homepage hero section. Also the stats row (e.g. "5 years experience", "12 shipped products").

Availability & Résumé

Toggle your hiring availability on/off with a custom status label. Upload your résumé PDF — it's stored in R2 and linked from the nav rail and mobile menu.

Maintenance Mode

Toggle to redirect all public pages to a maintenance screen while you update the site. Flip it back off when you're done.

CMS Collections

All content is managed in the Payload admin panel. Here's what each collection is for.

Work
Professional case studies shown on the Work page and homepage. Each entry has a title, description, category, display order, tags, cover image, detailed briefing (problem → approach → impact → quote), and tech stack list.
Timeline
Career history entries — company, role, start/end year, summary, and tags. Ordered by the order field.
Projects
Side projects, open-source work, Chrome extensions, mobile apps. Includes live URL, repo URL, category, tags, highlights list, and featured flag.
Posts
Blog articles with Lexical rich-text editor, code syntax highlighting, cover image, tags, featured flag, and draft/published status. Reading time is calculated automatically.
Education
Degrees and educational qualifications — institution, degree, location, years, GPA, and completion status.
Certifications
Professional certifications — name, issuer, year, and a link to the credential verification page.
Pages
CMS-managed static pages using either a basic or legal template. Use this for Privacy Policy, Terms of Service, or any custom page you want to manage without code changes.
Media
Images and files. Uploads are stored directly in your Cloudflare R2 bucket. Use the Media collection to upload cover images for posts and work entries.

Email Setup

1. Verify your domain in Resend

Log in to resend.com → Domains → Add Domain. Follow the DNS record instructions. Once verified, set RESEND_FROM_ADDRESS to an address on that domain.

2. Contact form

Set RESEND_TO to your personal email. When someone submits the contact form, you'll receive a notification email and they'll receive an auto-reply confirmation. Submissions are also stored in the Submissions collection in the admin.

3. Newsletter broadcasts

When you publish a new post, a broadcast is automatically sent to your Resend subscriber list. To use this:

  1. Create an Audience in Resend → Audiences
  2. Copy the Audience ID to RESEND_SEGMENT_ID
  3. Publish a post in the admin — the broadcast fires via a Payload afterChange hook
  4. Toggle the Skip newsletter field on a post to prevent broadcast for that specific post

4. Talent inquiry dialog

A dialog appears 15 seconds after a visitor loads any page, inviting recruiters to submit their opportunity. Submissions go to RESEND_TO with an optional job description attachment. You can enable/disable the form in the admin under Forms → talent-inquiry → Enabled.

SEO & OG Images

Metadata

Every page generates metadata dynamically from CMS data — title, description, OpenGraph, and Twitter card tags. The base URL and author name come from Site Settings → Identity.

OG Images

A Next.js route at /og generates PNG images on-the-fly with the page title, optional kind label, and description. These are automatically used as og:image when no cover image is set on a post or work entry.

JSON-LD Structured Data

Person, WebSite, and BreadcrumbList schemas are injected as JSON-LD on relevant pages. Google uses this for rich results.

Sitemap

A nested sitemap index at /sitemap-index.xml links to sub-sitemaps for static pages, writing, work, and CMS pages. All generated dynamically from the database.

Per-document SEO

Posts, Work, Projects, and Pages each have a Meta tab in the admin for custom title, description, and cover image overrides.

Analytics

Set NEXT_PUBLIC_GTM_ID to your GTM container ID to enable analytics. Leave it blank to disable GTM entirely — no scripts are loaded.

The following events are tracked automatically when GTM is active:

💡 The cookie consent banner is pre-wired to Consent Mode v2. Visitors who decline analytics are excluded from GA4 measurement automatically — no extra setup required.

Media & Storage

All media (images, PDFs) is stored in your Cloudflare R2 bucket. The R2 bucket must be set up with public access enabled so images can be served directly to visitors.

Enable public access on your R2 bucket

  1. In the Cloudflare dashboard, go to R2 → your bucket → Settings
  2. Under Public Access, click Allow Access
  3. Copy the public bucket URL (looks like https://pub-xxxx.r2.dev)
  4. Set both R2_PUBLIC_URL and NEXT_PUBLIC_MEDIA_URL to that URL
⚠️ If NEXT_PUBLIC_MEDIA_URL is not set, uploaded images will not display on the public site — only in the admin panel.

Deploy to Vercel

1
Push to GitHub
git init
git add .
git commit -m "initial"
git remote add origin https://github.com/yourname/payload-portfolio.git
git push -u origin main
2
Import in Vercel

Go to vercel.com/new, import your GitHub repository. Vercel auto-detects Next.js — no build settings needed.

3
Add environment variables

Under the project's Settings → Environment Variables, add all 16 variables from your .env.local. Make sure to set NEXT_PUBLIC_SITE_URL to your Vercel deployment URL (e.g. https://yourname.vercel.app).

4
Deploy

Click Deploy. The build takes 1–2 minutes. Once done, your site is live and the admin panel is at yoursite.vercel.app/admin.

5
Add a custom domain (optional)

Vercel Settings → Domains → Add. Point your domain's DNS to Vercel. Then update NEXT_PUBLIC_SITE_URL in Vercel's env vars to your custom domain and redeploy.

💡 The included vercel.json raises the serverless function timeout to 60 seconds to accommodate Payload's heavier admin API routes on cold starts.

Self-Hosted Deployment

Any Node.js 20+ host works. Build and start with:

pnpm build
pnpm start

A ecosystem.config.js (PM2) is included for process management on a VPS. Run with:

npm i -g pm2
pm2 start ecosystem.config.js

Refer to the Payload CMS deployment docs for self-hosted configuration details.

FAQ

The admin panel shows a blank page

Ensure MONGODB_URI is set correctly and your MongoDB Atlas cluster has the IP 0.0.0.0/0 in the Network Access allowlist (or your specific server IP).

Images don't show up on the public site

Check that NEXT_PUBLIC_MEDIA_URL is set and your R2 bucket has public access enabled. Also ensure the value doesn't have a trailing slash.

Contact form submissions aren't arriving by email

Verify RESEND_API_KEY, RESEND_FROM_ADDRESS, and RESEND_TO are set. The from address must be on a domain verified in Resend. Check the Resend dashboard logs for delivery errors.

How do I add a new legal page?

In the admin panel, go to Pages → Create New. Set the template to legal, add a slug (e.g. cookie-policy), and write your content. The page is live immediately at /legal/cookie-policy.

Can I add more social platforms?

The Social Links field supports GitHub, LinkedIn, Instagram, Twitter/X, and YouTube. To add more platforms, edit the options array in the socials field inside globals/SiteSettings.ts.

How do I disable the talent inquiry popup?

In the admin panel, go to Forms → talent-inquiry and toggle Enabled off. The dialog will stop appearing for visitors immediately.

The site shows "Your Name" instead of my name

These are fallback defaults that display when the CMS hasn't been populated yet. Go to Globals → Site Settings → Identity and fill in your name, role, and other details.
